# 星詠みの浮遊庭園: CPU対戦 v0.2

2026-10-01。ルール版 `floating-garden-match-1`。既存の採点定義（`floating-garden-prototype-1`）は変えていません。

## 入口と操作

- 自由配置／4人表示デモ: `lab/floating-garden/index.html`
- CPU対戦: `lab/floating-garden/match.html`。自由配置画面上部から移動できます
- 2〜4人（あなた1人＋CPU1〜3人）を選んで開始
- 自庭は大きく、相手は1〜3枚のプレビュー。相手をタップして拡大・自庭との比較
- CPUは「CPUの手を進める」を押した時だけ進行し、次に人間の選択が必要なところで必ず停止
- 画面上部の「操作・結果へ」から操作欄へ移動でき、公開タイルと流れの向きは判断ボタンの隣にも表示
- 自分の配置はマスを選び仮置き、必要なら90度回転、得点を確認して確定。仮置き取消は状態機械に影響しない
- 石も種類とマスを選んで仮置き後に確定。瞑想・提案・応答はボタンで確定
- 比較中・再戦確認中は背面操作を拒否。閉じる／Escape／native cancelでフォーカスとスクロールを復元
- 再戦／人数変更は確認を挟む。取り消せば仮置きや進行を保ち、実行時は古い操作要素を無効化
- タイマー・非同期CPU処理なし。CPU進行後も自動で次の手番に進まない
- 通信・アカウント・外部アセットなし。CPU対戦の最新1試合は同じ端末・同じブラウザーのlocalStorageへ自動保存。自由配置モードとは別セッション

## 途中保存・再開（2026-10-02）

- 保存キーは `floating-garden-cpu-match`、形式は `floating-garden-save-1`。CPU対戦の最新1試合だけを自動保存します。アカウント同期・別端末への引継ぎ・オンライン通信はありません
- 初回は人数を選び開始。保存がある場合は「続きから再開する」または新規開始を選びます。完成した記録は結果として再表示できます
- 新規開始・再戦・人数変更は保存の置き換えを明示して確認します。人数選択だけでは上書きせず、新しく開始するまで前の保存を保持します。取消・Escapeで保存を残します
- 全ルール状態を保存: 人数・席・盤面・配置タイルID・力・保管・山札と位置・公開タイル・提案相手・招き順/希望・配置先/保護代替・巡/段階・最終石・手入れ回数・ログ・revision。その状態へ至る合法コマンド履歴も保存します
- 各確定操作後に保存し、CPUの一括進行も1遷移ごとに保存します。残数アシストON/OFFも保存。再戦はOFFから始めます
- 仮置き、回転の選択、石の選択、比較/確認画面、詳細欄の開閉、スクロール/フォーカスは保存しません。復帰時は確定状態から選び直します。新たに引く処理やCPU進行はしません
- 復元はJSONの読込みだけで済ませず、版・型・サイズ・フィールドを検証し、初期状態から合法コマンド列を再現して全状態と照合します。不正な席/段階、重複タイル、山札や力の改変、余分なフィールド、不整合なログも拒否します。破損・旧版は修復・削除・上書きを勝手に行いません
- Web Locks APIで、対戦を開いている間は同じ保存の書込み権を1タブだけに限定します。他のタブは保存の説明を読めますが、元のタブを閉じるまで保存付きの再開・新規作成はできません。書込み直前にも保存文字列を比較します
- 別タブ/ブラウザー操作による保存の変更や戻る操作のキャッシュ復帰では進行を一時停止します。保存を読み直す場合は画面だけの未保存進行を破棄する確認を挟みます。「この画面だけで続ける」は保存を変更しない明示的な選択です
- 容量不足・書込み拒否では成功した最後の保存を残し、最新状態はこの画面で保持して進行を停止します。「保存を再試行」か保存なしの続行を選べます。CPUの処理途中でも、失敗した1遷移の直後に止まります
- localStorageの読込み自体が拒否される環境、Web Locksを使えない環境では保存なしと表示し、既存データを変更しません。ブラウザーのデータ削除、プライベートブラウズの終了、端末故障などから保存を保護するものではありません
- 保存内容は端末内の平文です。画面やCPUへ山札順・シードを渡す設計ではなく、保存ファイルの表示/書き出し機能も追加していません。開発者ツールからローカル状態を読むことを防ぐセキュリティ境界ではありません

## 図つきの採点お手本

「対戦のルールと操作」の採点欄に6つのお手本を追加。開始前・対戦中のどちらでも、必要な項目だけ開けます。

- 流れ: 異なる地形でも向きが合う1辺は1点。向きの不一致・斜め・盤外は対象外
- 月読み: 足元を含む同じ横列の湖4枚、8点から上限6点へ
- 風守: 上下左右の雲海2枚で4点。斜め・足元・別地形は対象外
- 彩り: 隣接4枚でも湖が重なれば3種類で6点。斜めと足元は対象外
- 共鳴: 同じ縦横の別の石2個で4点。間の空きは可、自分と斜めは対象外
- 四隅: 四隅4種類で4点。中央の種類は関係せず、重複・空きは0点

`match-rule-examples.js` の固定盤面を既存 `scoreGarden` で採点し、表示点・式・得点対象の光枠を生成します。盤面は閲覧専用、既存 `tileArt` SVGを再利用。地形の記号凡例、座標、石の名前、光枠／金の石／対象外の×と点線で色以外でも意味を説明します。図の得点がその採点項目だけであることも明記しています。

例の開閉はnative `details` のみで、ゲーム用ボタン・選択インデックス・ハンドラーを持ちません。対戦の状態機械・CPU・採点数値は変更なし。既存の描画時の開閉保持で、仮置きや比較後も開いた例を保ちます。ブラウザー用モジュールとCSS参照の版番号を `20261001-rule-examples` にそろえました。

## 仮ルール

4×4の庭、地形5種、直線／曲線、回転4方向、石4種は既存の定義通りです。

### 力

初期4、上限6。瞑想+1、譲渡成立+2、招く3、庭に迎える2、石3。増加が上限を超えた分は切り捨て。余力の得点なし。

### 自分の手番

1. 未完成なら、保管していた1枚を使うか、山札から1枚引いて公開
2. 自用／未完成の相手1人へ譲る提案／保管を選ぶ（保管から取り出した1枚は再保管不可）
3. 自分の庭に必ず1枚配置するまでタイルの処理を続ける
4. 手入れを1回: 瞑想または石1個。完成済みなら1〜3を飛ばし手入れのみ

自用を選ぶと招きの応答段階に入るため、この後は保管や譲渡へ戻れません。確定配置の上書き・移動・回転・石の交換・1手戻すはありません。

### 譲る

- 同じ手番で提案できる相手は1人だけ。完成者に提案不可
- 相手が受けると相手が直ちに配置、元の手番の人は力+2
- 元の手番の人は保護代替を1枚引き、必ず自庭へ配置
- 拒否なら自用または保管へ。別の人に提案し直せない
- 保管から使った1枚を拒否された場合は自用のみ

### 保管

- 1枚まで。空きなら今の1枚を保管して保護代替を必須配置
- 満杯なら新しい1枚を保管し、前の1枚を自用として処理
- 前の1枚を別の人へ提案したり保管し直したりはできない
- 完成時に保管が残っても盤面を壊して使わない。終局在庫として保持し得点にしない

### 招く・庭に迎える

- 自用とした未配置の1枚を、未完成かつ力3以上の他者へ公開
- 希望確認は公開優先マーカーから席順に全員へ。希望後撤回なし
- 複数の希望があれば、同じ優先順で最初の1人が候補
- 持主は力2で庭に迎えるか、渡す。力2未満なら迎える操作は表示せず、理由を表示
- 迎えたら持主だけ力2支払い、その1枚を配置。他の人は力を使わない
- 渡したら実際に受け取る人だけ力3支払い即配置、元の手番の人は保護代替を必須配置
- 成功時、優先マーカーは**受け取った人の次の席**へ。防いだ場合は移動しない
- 受贈与タイル、招きで受け取ったタイル、保護代替、仕上げ中のタイルへは招けない
- 配置済みの庭は常に保護される

### 巡と終局

- 通常12巡。その後は仕上げ最大4巡（通算13〜16巡）
- 仕上げは保管を先に使い、なければ1枚引き、必ず1枚配置。譲渡・保管・招きなし
- 途中で全庭が完成しても、その巡の最後の席まで手入れを継続
- 完成が通常12巡より早ければ、その巡末で最後の石へ進む
- 全員同数の手入れ後、席順に手持ちの力で最後の石を最大1個またはパス
- 既存の流れ・石・共通お題を再計算。同点同順位（例: 1位、1位、3位）

### 今回明文化した境界条件

以下はルールの未確定部分を大きく変えず、状態機械のために採用した仮定です。

- 保管から自用にした1枚（満杯保管との交換を含む）も、通常巡は他者の招き対象。取り出したという理由だけでは保護しない
- 満杯保管から出した旧タイルは自用に固定。招き成立なら通常通り保護代替を配置
- 招き希望は優先順に全候補から集めた後に持主が応答。先の希望者の有無は公開情報
- 初期の招き優先マーカーはP2、通常手番は常にP1から席順
- 最終石には追加の瞑想・力補充はなく、パスするとその人の配置は終了
- CPU強度・点数のバランス、席順の公平性は今後のプレイ調整対象。終了性のテストはバランスの保証ではない

## 山札・終了性・保存則

画面の開始時はブラウザーの乱数UUID（利用不可なら時刻）をシードとして渡し、再戦ごとに別のシードにします。テストでは明示的な固定シードを渡します。ランダム生成はUI側だけで、状態機械・CPUの内部では乱数や時計を使いません。

人数Nに対して20N枚。5地形×2形状×各2N枚を、外部から渡したシードで決定的にシャッフルします。CPUはシード・山札・山札カーソルを渡されず、公開状態だけで考えます。ローカルゲームの内部データそのものを秘密にするセキュリティ境界ではありません。

各物理タイルには一意のIDを付け、未使用山札／公開中1枚／各庭の配置ID／保管のちょうど一つに所属します。破棄・複製・二重使用はなし。庭への配置ではIDと地形・形状の一致も検証します。盤面の回転と石だけが元タイルとの差分です。

各自分の手番で未完成庭は必ず1マス進むため、16巡を超えません。他者の手番から受け取る分は完成を早めます。各人の最終保有は庭16＋保管1で最大17枚。公開中のタイルがある時も、まだ埋まっていない配置先があるため同じ上限を超えません。最大消費17N枚で20N枚の山札に3N枚以上が残り、正常な遷移では枯渇しません。

## 実装の境界

- `match-engine.js`: シード山札、状態生成、合法コマンド列挙、不変状態遷移、公開状態、順位、資源・在庫・回数のinvariant
- `cpu.js`: 公開状態と合法コマンドから1つ選ぶ純粋CPU。接続点、四隅、将来の石の配置意図を評価。即時石得点・力の確保・保管・譲渡・招き・防御を使い分ける
- `match-view.js`: 庭・公開情報・操作・応答・結果・比較のHTML
- `match-app.js`: 手動CPU進行、仮置き、比較ダイアログ、再戦確認、古い操作要素の無効化
- `match.html` / `match-style.css`: CPU対戦専用入口と最小限のレイアウト追加
- 既存採点・自由配置のルールは変更なし。既存app/viewは入口説明と版番号、session/table-demoはimport版番号だけ更新

状態とコマンドはJSONにでき、同じシード＋同じ合法コマンド列で同じ状態へ到達します。各コマンドは`seat`と`revision`を持ち、別席・古い手番・余分な入力を拒否します。将来の通信は実装していません。公開状態から権限のあるサーバー状態を再構築する設計でもありません。
