# 星詠みの浮遊庭園（仮題）: 配置／採点と4人表示の試作

作成日: 2026-10-01。自由配置の仮ルール v0.1。数値、名称、素材の構成は調整前提です。

CPU対戦を別モードとして追加しました。最新の進行ルール・入口・検証範囲は [CPU対戦 v0.2](floating-garden-cpu-match.md) を参照してください。以下は自由配置と固定4人デモの仕様です。

## この段階で試せること

- 4×4の庭に、5種類の地形と直線／曲線の流れを自由に選んで置く
- 選んだ地形を90度ずつ回す。仮置き中にも回せる
- 4種類の石を各1個、地形のあるマスに置く
- タップで選択 → マスをタップして仮置き → 得点を確認 → 確定
- 仮置きの取り消し、検証用の「1手戻す」、見本の庭、空の庭へのリセット
- 合計、つながった辺、石ごとの対象マス／種類数／上限適用、共通お題の自動採点

素材は自由に何度でも選べる**配置・採点の実験室**です。山札や引いた1枚を選ぶ対戦を再現するものではありません。通信・保存・アカウント・外部アセットは使用しません。リロードやページを閉じると配置は消えます。サイトの既存一覧には追加していません。

「1手戻す」は数字と動作の検証用です。本編で確定済みの庭を動かせるという意味ではありません。

## 今回の採点定義

### 庭と流れ

- 列は左からA〜D、行は上から1〜4
- 地形は雲海・月光湖・結晶原・精霊林・魔力地
- 回転0の直線は上下、曲線は上と右に流れが接する。回転1は時計回り90度
- 上下左右に隣り合う2枚で、向かい合う辺に双方の流れがあれば1点
- 地形の種類は接続条件に影響しない
- 同じ辺は1回だけ加点。斜め、盤外、空きマス、片側だけの流れは加点しない
- 確定したタイルの上書き・移動・回転は不可。地形を置く場所に隣接制限はない

### 星の石

各種類1個、1マス1個。地形のあるマスだけに置く。確定後の移動・交換は不可。得点はその時点の庭全体から毎回再計算します。

| 石 | 1単位あたり | 対象 | 上限 |
| --- | --- | --- | --- |
| 月読み | 2点／枚 | 同じ横列にある月光湖。**自分の足元が湖ならそれも数える** | 6点 |
| 風守 | 2点／枚 | 上下左右に隣接する雲海。足元・斜めは数えない | 6点 |
| 彩り | 2点／種類 | 上下左右に隣接する地形の種類数。同じ種類が複数あっても1種類 | 6点 |
| 共鳴 | 2点／個 | 同じ横列または縦列にある**別の石**。自分は数えない | 6点 |

彩りの補足:

- 空きマス、足元、斜めは数えない
- 隣接する地形が足元と同じ種類でも、その隣接地形は1種類として数える
- 4つの隣接マスが「雲・雲・湖・湖」なら2種類で4点
- 4つがすべて異なるなら計算上8点だが、上限適用後は6点
- 角のマスの対象は2マスだけ。D1とA2など行をまたいだ左右は隣接ではない

共鳴は距離に関係なく同じ列・行の他の石を数える。途中の空きマスや別タイルは遮らない。4種類各1個なので最大対象は他の3個です。

### 共通のお題と合計

- 「四隅異なる地形」: A1・D1・A4・D4がすべて埋まり、それぞれ別の地形なら4点
- 試作は途中の庭も採点するため、四隅が完成した時点から加点する
- 合計 = つながる辺 + 石4種類の得点 + 共通お題
- 余力の得点はなし

月読みが足元を含むことなど、未確定だった境界条件は今回の**試作用の定義**として上記の通り固定しました。対戦版で決定を変える場合はルール版とテストを一緒に更新します。

## 見本の庭（期待値31点）

「見本の庭」→「見本に切り替える」で決定的な同じ盤面を読み込めます。

- 流れ: 9点
  - A1–B1、A1–A2、D1–D2、D2–D3、B3–C3、D3–D4、A4–B4、B4–C4、C4–D4
- 月読み B1: 同じ行の湖B1・C1で4点
- 風守 C2: 隣接する雲海D2・C3で4点
- 彩り B3: B2（月光湖）・C3（雲海）・B4（精霊林）・A3（魔力地）の4種類。8点を6点に制限
- 共鳴 B4: 同じ列の月読みB1・彩りB3で4点
- 四隅: 雲海・結晶原・月光湖・魔力地で4点

## 実装の分離

- `lab/floating-garden/engine.js`: 庭・タイルの生成、入力検証、不変配置、隣接、採点。DOM・通信・時計・乱数から独立した純粋関数
- `lab/floating-garden/session.js`: 選択、仮置き、回転、確定、取り消し、履歴復元の決定的状態遷移
- `lab/floating-garden/view.js`: 庭と採点結果からHTMLを生成。地形名・座標・接続・石を文字でも示す
- `lab/floating-garden/app.js`: クリックとEscapeの処理、フォーカス維持、見本／リセットの確認
- `lab/floating-garden/style.css`: モバイル向け単列、デスクトップ向け2列、44px以上の主要操作、色だけに頼らない識別

この自由配置モードでは本編のコマンド検証・乱数シード・手番進行を扱いません。現在の採点関数には対戦、CPU、サーバーのいずれからも同じ公開された庭を渡せます。「1手戻す」の履歴は試作UIに限定し、本編の許可コマンドに含めない想定です。

## 次段階に向けた仮ルール（当初の記録。現在は別モードで実装済み）

世界観は幻想的で静かな庭づくり。公開タイルと公開の庭を見て、引いた1枚を自分で使うか譲るか判断します。「奪う」ではなく精霊を「招く」、防御は「庭に迎える」という表現を使います。既存の庭は壊れず、最後は全員の庭が完成する方針です。

- 4×4、地形5種類、流れは直線／曲線で回転可能
- 各手番に自分の庭が1枚分進む。譲渡／招き成立時にも保護代替1枚を置く
- 保管は1枚
- 通常12巡 + 仕上げ最大4巡
- 全員が埋まった巡末まで、完成済みの人にも手入れの手番を用意する
- 最後の石配置は1個またはパス
- 力: 初期4、上限6。瞑想+1、譲渡+2、招く3、迎える2、石3
- 余力を得点にしない

上記の譲渡、招き、保護代替、保管、力、12巡と仕上げ、最終配置、CPUは後続の別モードで実装しました。オンライン通信は未実装です。この試作の自由な素材選択、無制限の石配置タイミング、1手戻すは本編の手番制限を検証したことにはなりません。現在の状態機械・決定的な山札・CPUの仕様は上記リンクを参照してください。
