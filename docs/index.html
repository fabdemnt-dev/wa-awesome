1. 画面構成

トップページ

「ポエム工房」「俳句の庭」「神の手札」の順に入口を並べ、訪問カウンタを表示します。現在の見た目を維持します。

ポエム工房

言葉カードと自由入力で作品を作る画面です。名前とルームIDを入力して参加し、同じルームの人と素材・作品を共有します。

俳句の庭

五・七・五のカードを選んで一句を作る画面です。句会の進行、親の役割、評価方法の詳しい仕様は今後確認します。

神の手札

ポエム・俳句で使うワードセットを管理する画面です。作成・編集・再利用の詳細は今後確認します。

2. ポエムの遊び方

入室・素材の準備

プレイヤーまたは見学者として入室します。ロビーでプレイヤーが言葉を投稿し、全員分の手札に必要な素材を集めます。標準セットや選択したワードセットから不足分を補充する機能があります。

開始

準備ができたら、参加プレイヤーの誰でも開始できます。親や最初の参加者である必要はありません。必要素材数は「プレイヤー数 × 手札枚数」です。素材が足りなければ開始できません。

作品を作る

配られたカードを押すと、入力欄のカーソル位置に言葉が入ります。自由に文章を入力することもできます。カードの選択状態は、作品と一緒に記録する使用札に対応します。

投稿・披露・鑑賞

作品を投稿し、披露された作品をみんなで読みます。投稿は1回の作成につき1作品です。送信中は入力・リセット・再投稿を止めます。投稿には作成回を付け、次の回に遅れて届いた投稿は手札の有無にかかわらず保存しません。披露された作品にはリアクションを付けられます。いいね・エモいは「処理中」と表示せず、送信中のボタンを薄くして同じ作品への同種リアクションの二重送信を防ぎます。ボタンの文字と件数は保持し、送信・画面反映に失敗したときは通知します。音声読み上げ、文章コピー、CSV出力の機能があります。コピーした文章のDiscordへの投稿は利用者が行います。

コピー・CSV

現在の回だけ、または過去の履歴を含めて出力できます。出力対象は投稿済みの作品で、披露前の作品も含みます。未投稿の下書きは含めません。作者名はその回に保存した名前の対応を使います。CSVはUTF-8（BOM付き）で、引用符・カンマ・改行・「#」を含む名前や本文を保持します。コピーに失敗した場合は通知します。

次の回

「新しいポエムを作る」で作品を履歴に保存し、ロビーに戻ります。履歴にはサーバー上の最新の投稿作品・使用札・披露状態・リアクション数・作者の対応を保存します。保存と同時に素材・手札・現在の作品を空にして、新しい回の準備を始めます。複数人が同じ回で進行操作をしても進むのは1回だけで、古い画面から次の回の作品を消すことはありません。未投稿の下書きは履歴の作品には含まれず、次の回へ持ち越しません。

俳句：プレイヤーと見学者の切り替え

ロビーと句会中のどちらでも、プレイヤーと見学者を切り替えられます。ただし、進行不能を防ぐため、今節の選者（親）は句会中に見学者へ切り替えられません。

子が句会中に見学者へ切り替わっても、今節の参加記録、手札、引き直し済み状態、選択中の五・七・五、投稿済みの句、披露状態、自画自賛、御印を削除しません。同じ節でプレイヤーへ戻った場合は元の状態を使い、新しい手札を配ったり山札を減らしたりしません。まだ今節に参加していない見学者がプレイヤーになる場合だけ、途中参加として手札を配ります。

見学中は作句欄と引き直し操作を隠し、手札欄に見学中の案内を表示します。参加者一覧ではプレイヤー側から見学者側へ移り、戻ったときはプレイヤー側へ復帰します。

3. 参加と操作

プレイヤー

素材投稿、ロビーでの手札枚数変更、開始、自分の作品の投稿、自分や他のプレイヤーの作品の披露、次の回への進行ができます。開始はロビーでのみ行えます。開始済みの回に再び開始要求を送っても、手札を配り直したり、作品を消したりしません。

見学者

参加者の準備状況や披露された作品を見て、リアクションを付けられます。素材投稿・手札枚数変更・開始・作品投稿・作品の披露操作・次の回への進行はできません。

役割の切り替え

ポエムには親の役割を設けません。プレイヤーは全員対等で、参加順による操作権限の差はありません。作成中でも見学者へ切り替えられます。見学中は手札・入力欄・投稿／リセットボタンを隠し、案内文を別の場所に表示します。作品の鑑賞・リアクション・コピー・CSV出力は引き続き利用できます。同じ回でプレイヤーに戻る場合は元の手札を使い、手札をまだ持たない途中参加者にだけ配札します。投稿済みの作品は役割を切り替えても残り、再投稿はできません。

4. 下書きと次の回

入力途中の文章は同じタブのセッション内で保存します。同じルーム・同じ利用者・同じ回への復帰では本文とカードの選択を復元します。見学への切り替えでは下書きを消さず、同じ回でプレイヤーに戻ったときに復元します。「見学モード中」という案内を本文へ書き込むことはありません。

回が変わったときは、入力途中の文章とカードの選択をリセットします。ブラウザを離れている間に次の回が始まった場合も、前の回の下書きを表示しません。別のルームや別の利用者の下書きも復元しません。

投稿成功またはリセット操作で保存済みの本文とカード選択を消します。保存を確認できなかった場合は下書きを残します。保存成功後に画面更新だけが失敗した場合は「投稿は保存済み」と知らせ、再投稿を止めたまま手動更新を案内します。前の回・別ルームへの投稿の完了は、現在の下書きやカード選択を消しません。投稿済みの場合は入力と投稿／リセット操作を無効にします。下書きは投稿作品とは別で、サーバーへ作品として自動投稿されるものではありません。

5. 画面の同期

ポエムは入室成功時に、同じタブのsessionStorageへ部屋IDと利用者UIDを保存します。ページが再読み込みされた場合も、本人の参加登録をサーバーで確認して元の部屋を表示します。役割は現在の登録を引き継ぎ、復元時に部屋作成や参加登録の書き込みはしません。通信失敗時は再接続でき、部屋や参加登録がない場合は入室画面に戻ります。別の部屋を指定したリンクでは自動復元しません。時間による期限は設けず、通常はタブの終了まで保持します（ブラウザのセッション復元で残る場合があります）。

同じルームの開始状態、参加者、素材、作品、リアクションを受信して表示を更新します。ブラウザへ戻ったときは最新のルーム状態を取得し、開始済みなら作品作成画面へ切り替えます。

復帰時には以前の取得待ちを引き継がず、新しい取得を開始します。復帰前の取得が後から完了しても、その結果で画面を戻しません。取得は10秒でタイムアウトし、再試行できる状態に戻します。

表示中は5秒間隔の補助取得を行います。手動の「最新の状態に更新」も利用でき、失敗した場合は通知します。通常の画面更新で入力イベントが重複登録されることはありません。

6. 基本設計

構成

GitHub PagesでHTML・CSS・JavaScriptを配信し、Firebaseの匿名認証、Firestore、Cloud Functionsを使います。Firebaseの利用者UIDで参加者を識別します。

ルームとデータ

ポエムのルームはFirestoreの rooms/poem_{roomId} に保存します。status は lobby または playing、roundCount は作成回を示します。参加者名とUIDの対応、素材、UID別の手札と作品、手札枚数の設定を保持します。過去の作品は history サブコレクションに保存します。

開始処理

poem-game.js から dealPoemHands を呼びます。サーバーは認証、プレイヤー所属、ルーム形式、ロビー状態、UID対応、素材数を確認し、トランザクションで配札と状態変更を一括実行します。

操作権限

設定と披露はプレイヤー所属で判定します。新規ルームに親情報を作りません。旧ルームの親情報は権限判定に使わず、開始・設定・役割変更・披露・退出の更新時に削除します。親の引き継ぎは俳句専用です。

同期処理

poem-room.js でSnapshotを購読します。メタデータ変更も受信し、キャッシュからサーバー確認済みに変わった時点で反映します。復帰時には取得世代を更新し、古い世代の取得結果を無視します。表示復帰・ページ復元・フォーカス復帰で最新状態を取得します。

履歴保存と読み込み

poem-game.js はトランザクションで最新ルームを読み、開始状態・作成回・プレイヤー所属を再確認します。履歴サブコレクションへの新規記録の作成と次の回への初期化を一括確定し、競合した場合は最新状態で再確認します。履歴の購読は room-history.js でメタデータ変更も受け取り、キャッシュを除外しつつサーバー確認済みの履歴を反映します。この購読処理は俳句とも共用します。

投稿処理

submitPoemSecure は必須の expectedRound とサーバーの作成回をトランザクション内で照合します。回の情報がない旧画面からの投稿は拒否し、再読み込みが必要です。画面側は送信時のルーム・利用者・回と保存済み状態を保持し、保存成功と再同期失敗を区別します。再同期中に回やルームが変わった場合、旧処理による入力の初期化と成功通知を抑止します。

下書き

poem-action.js でsessionStorageに本文・選択したカードIDと「ルームID・利用者・回」の対応を保存します。カード選択は現在の手札のIDに照合して復元します。対応が一致した下書きだけを復元し、回の変更時は保存本文と画面上の入力・選択をリセットします。回が判別できない旧形式の下書きは自動復元しません。

7. 確認する項目

ポエムの見学切り替えと同じ回への復帰、次の回での初期化を実端末でも確認します。俳句は役割切り替え以外の挙動を順番に確認し、ワードセットとあわせて詳細仕様をこのページに追加します。

開始は2人目のプレイヤーから成功したとの利用者確認済み。ブラウザ復帰と下書き切替は単体テストで確認していますが、実端末での改善と通信遅延の実測は引き続き確認が必要です。
